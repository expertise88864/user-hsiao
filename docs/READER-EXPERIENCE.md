# 一般衛教與醫師研究筆記：閱讀與成效

## 文章標題與搜尋摘要工作區

短視窗與瀏覽器放大後，底部工具列限制在視窗高度的 40%，其餘按鈕可在工具列內捲動；避免遮住標題／摘要輸入位置。標題中的 `&`、`<…>` 是作者文字，保存再開啟及切換語言仍以文字顯示；原有未修改的雙語格式保留。輸入摘要不重建整頁或解析 JSON-LD，只有主標題修改才更新可見標題。

視覺編輯器從 authenticated GET 讀取文章與目錄版本，頁首主標題也取自該文章來源。作者可分別修改中英文主標題、中文搜尋標題及中英文摘要；未動到的欄位保留原本不同的文字與排版。英文摘要留空時，生成器沿用正文的英文摘要，沒有自動翻譯或新增醫療宣稱。

欄位與正文共同參與復原／重做、離開時的本機草稿、完整來源匯出、預覽及三版本比較。字數是寫作參考，不是搜尋排名分數；搜尋引擎可能重寫顯示標題／摘要。既有存檔流程仍會正規化中文旁的標點。

主標題變更與文章目錄在一次 Git 提交中保存。復原草稿保留原本的目錄版本；伺服器以該歷史版本核對這篇文章的中英文標題。只有其他文章或產生物改變時，可沿用最新目錄保存，保留其他人的修改；這篇標題已變更、歷史版本無法確認，或原子保存時版本再次變更，都會回報衝突並保留草稿，不能用舊版本覆蓋新內容。保存回應提供下一次修改所需的目錄版本；舊瀏覽器收到缺少目錄版本的來源時，主標題欄位不開放修改。保存至 GitHub 仍不等於正式發佈通過。

這個工作區不改 URL、作者身分、文章分類或原始發布日期；不會替作者改寫既有文章。分享圖片內的文字仍是獨立的圖片資產，主標題修改後應在正式候選預覽確認圖片內容。

使用者於 2026-09-06 選定兩類內容並重。首頁提供同等入口；文章保留完整醫療與研究內容，讓讀者自行選擇閱讀深度。不以停留更久或點擊更多頁，單獨判定讀者是否得到幫助。

## 本輪實作

- 首頁：一般衛教與醫師研究筆記各有入口、說明與三個起讀連結；純 HTML 即可操作。
- 青光眼指南、白內障手術選擇、DREAM 研究：標題後提供四個靜態段落捷徑；保留原摘要、警訊、正文、引文及發布日期。
- 淚腺腫瘤、乾眼迷思、飛蚊症、兒童近視：以既有問題與段落提供四個入口，不增加醫療結論；中英文導覽分別指向各自正文的原有 id。五篇試點中的青光眼沿用原導覽。
- 舊文章的 `proseZh`／`proseEn` 雙正文：英文生成頁預設顯示已有英文正文，中文來源保持原狀。沒有 JavaScript 仍能閱讀英文與使用段落連結；語言切換繼續由原共用程式處理。

四篇既有英文鏡像仍屬不完整翻譯，保留 `EN_STUB_SLUGS`、noindex 與原發現邊界。顯示已有英文不代表解除發布門檻：淚腺文缺英文分期／追蹤等段落，乾眼與近視缺健保及部分表圖，飛蚊英文缺兩張正文圖。英文發布檢查除原語言比例、canonical、hreflang、noindex 與發現檔案外，另查雙正文的段落 id 與表圖覆蓋；發現覆蓋缺口仍不能進英文索引。結構相同亦不代表醫療翻譯核可，不藉此次導覽變更解除四篇鏡像限制。
- 推薦：同疾病 → 同臨床主題群 → 同內容分類 → 日期 → slug。固定排序不依賴亂數，不改既有雙向文內連結。
- 搜尋：詞彙正規化、繁簡常見字形及中英文同義詞；多詞查詢須同時符合各詞。無結果時提供主題地圖、量表入口。搜尋詞不代表診斷。
- 閱讀統計：累計前景時間，隱藏及預先渲染期間不累計；30 秒與 2 分鐘事件各一次。article_read 使用同一時間來源。
- 效能：鎖定 web-vitals 版本、獨立產生並延後載入 assets/vitals.min.js。維持既有 CLS ×1000 儲存單位；新舊算法的數值不宜直接作前後改善比較。第一方統計有新版樣本時只計新版，依 metric ID 去重；回應 method 區分新舊來源。
- 維護：reader-metrics、reader-search、reader-navigation、vitals 各自管理單一責任；npm run minify 建置兩個產物，檢查器驗證兩者位元組一致性。

## 上線後觀察

### 後台效能指標的資料限制

`/api/admin/cwv` 優先使用第一方原始樣本，p75 採排序後的 nearest-rank（第 ceil(0.75 × N) 筆）。每項指標最多讀取最近 1,000 筆回報，僅保留所選滾動期間內、最多 30 天的樣本；標準量測依 metric ID 去重，樣本數不是不重複訪客數。90 天選項不會把第一方儲存擴充成 90 天完整分布。

GA4 備援僅能提供事件總值／事件數的平均值，p75 保留 `null`，不以平均值乘係數推估百分位或判定 Core Web Vitals 通過。GA4 所選曆日包含尚未結束的今天，與第一方滾動期間不同。第一方樣本判讀也不等於 Google CrUX 或 Search Console 結果。

已確認沒有可用樣本時，`status` 為 `no_samples`、樣本數為零、平均值與 p75 為 `null`；設定缺失或讀取失敗時為 `unavailable`、樣本數亦為 `null`。實測為零仍顯示零。單一來源或指標失敗保留其他有效結果，`issues` 與 `collection` 說明來源狀態；環境設定存在不代表已確認正式收件。快速切換期間時只呈現最後一次請求的結果。

先記錄確實上線的 SHA／日期及統計定義改版日，排除預覽、管理者與測試流量；核對 GA4 收件，缺資料不是零互動。以完整 28 天比較台灣非指名曝光、文章點擊與相近排名條件下 CTR，樣本少則延長。分別觀察一般衛教與研究入口的使用，不事先宣稱流量增加。

### 公開量測的資格與收件

既有頁面及兩種新文章範本共用 `assets/telemetry.js`。只有正式 HTTPS 網域的一般讀者啟用 GA4、Vercel Web Analytics／Speed Insights 及第一方 Web Vitals、搜尋、A/B 計數；Preview、localhost、已知機器人／webdriver、管理頁及 `?admin=1` 排除。DNT 或 Global Privacy Control 開啟時不蒐集。預先渲染期間不啟用，啟用頁面後才註冊一次。

成功登入會保留原 HttpOnly HMAC session，另設八小時的 `hs_telemetry_optout=1` 匿名標記；它不含訪客識別資訊、不能登入或授權。登出僅清除 session，標記在剩餘有效期間仍排除編輯者瀏覽。送出時重查標記；GA4 的 `ga-disable` 與 Vercel 的 `beforeSend` 也排除已開啟分頁後來產生的事件。第一方端點另查正式環境、來源及有效管理者 session，不以客戶端判斷代替伺服器檢查。這些是資料品質篩選，不能辨認所有偽裝成人類的流量。

`sendBeacon` 回傳成功只代表浏览器接受排隊。CWV／A/B 回應的 `stored: true` 才代表儲存呼叫成功；未設定或排除是 `stored: false`，CWV 儲存失敗回傳錯誤。搜尋紀錄仍採原本明確啟用的匿名彙總政策，204 不證明寫入。正式 GA4 與 KV 收件必須於部署後另行核對，不以模擬測試、設定存在或候選 Preview 證明正式收到。

送出阻擋依據：[Google tag 的 ga-disable](https://developers.google.com/tag-platform/security/guides/privacy)、[Vercel Web Analytics beforeSend](https://vercel.com/docs/analytics/package)、[Speed Insights 官方載入程式](https://github.com/vercel/speed-insights/blob/main/packages/web/src/generic.ts)。診斷用錯誤紀錄與公開成效統計用途不同，不由本次篩選變更其既有錯誤蒐集政策。

尚待實測決定：將閱讀路線擴展到其餘文章、長摘要的逐段醫療編輯、更多按需載入拆分。依實測與站主內容核可推進，不能把本輪導覽調整當成全站正文重寫完成。

### 編輯草稿與安全離開

重新開啟時會比較 OPFS 與 localStorage 兩份可讀草稿的時間，選取較新的快照，保留另一份。OPFS 可讀但不能寫入時，不能優先恢復舊 OPFS 而忽略已確認寫入的新 localStorage 備援。同分頁寫入使用單調遞增時間，避免同一毫秒的備援快照排序相同；重新讀取會延續已知草稿時間。舊版缺時間或相同時間的草稿保留 OPFS 優先，不自動刪另一份；尚不代表完成所有多分頁衝突隔離。

同一瀏覽器、同一網站中的同篇文章，視覺編輯器在讀取來源、恢復草稿及開啟輸入前取得 Web Locks 排他鎖，並持有到編輯文件關閉。第二分頁顯示原因及「重新開啟編輯」，不讀取、覆寫或清除該文章草稿；不同文章仍可同時編輯。正常離開先保存最新草稿，離開失敗則繼續保有編輯權；GitHub 保存成功本身不釋放編輯權。初始化失敗會釋放，文件關閉／終止由瀏覽器釋放；不在可以取消的 beforeunload 事件提前釋放。

瀏覽器缺少 Web Locks 或拒絕請求時，保留原草稿且不開啟可寫編輯模式，顯示失敗原因與重試入口。這項保護適用使用此新版編輯器的分頁，舊版已開啟分頁需重新開啟；不同瀏覽器／裝置的公開保存衝突仍由 baseSha 處理。實測覆蓋 Chromium 的 OPFS／localStorage、正常離開、已確認草稿後的強制關閉、初始化與保存失敗及不同文章；不據此宣稱所有瀏覽器、未確認輸入的崩潰復原或 IME／Undo／Redo 已驗收。[Web Locks 規範](https://www.w3.org/TR/web-locks/#motivating-use-cases)

視覺編輯器的「回到後台」與「離開編輯」會先寫入最新本機草稿；寫入失敗時保留編輯器與內容，GitHub 儲存尚在執行時請等候結果。草稿寫入與刪除依序執行，保存期間的新輸入仍須保留。重新整理或直接關閉分頁會在有未儲存修改時顯示瀏覽器離開提醒；瀏覽器強制終止、使用者仍選擇離開或儲存不可用時，不能保證最後一次輸入已保存。

保存狀態持續顯示，分別說明尚未儲存、本機草稿、GitHub 已保存及正式上線尚未確認。GitHub 成功後若又有新輸入，顯示上一版已保存但新修改仍未儲存；不把先前成功訊息當成最新內容或正式部署完成。「丟棄」需明確確認、清除本機草稿並重新讀取來源，清除期間的新輸入保留在編輯器。

刪除草稿須確認 OPFS 與 localStorage 中皆不存在；刪除或驗證讀取失敗時不回報已清除，也不因讀取失敗得到 `null` 就允許丟棄。GitHub 已保存但本機清理失敗會持續顯示錯誤，禁止把已保存的 commit 再排入離線重送。環境頁使用 API 的 `configured` 判斷設定存在與否，回應快慢不代表 KV 設定或收件；A/B 計數與 Builder 設定的儲存路徑不同，Builder 的 GitHub 備援仍保留。

HTTP 成功狀態仍須有可解析、有效的文章 SHA 與 commit 回執；無改動的回執可明確使用 `noop` 與空 commit。成功狀態但回執损壞時，保留原 baseSha 與草稿、顯示版本未確認並阻止重複送出，不刪除草稿、不排離線重送；需重新開啟取得新來源與版本。這項保護不等於能證明未收到任何回應的網路失敗是否已由伺服器寫入，既有離線路徑仍依原版 SHA 防止覆寫。

本輪實測已證明原先的立即關閉會在五秒自動保存前遺失內容，OPFS 與 localStorage 備援皆適用。雙語草稿復原原本已保留整個 article：CSS 選擇器清單按文件順序選到 article，而非優先選 proseZh；未為此改寫復原路徑。此狀態改善尚不包含真正的候選／正式部署狀態查詢、完整雙語標題編輯、IME／Undo／Redo 或所有 CMS 工作流程驗收。

### 預設字級與載入排版

文章的螢幕樣式預先使用閱讀控制項原有的中等字級（16.5px），減少延後啟動控制項時再次調整整篇正文的排版。儲存的小／大字級偏好與控制項切換仍由原有偏好樣式覆蓋；這項預設僅適用螢幕，不改列印樣式。未啟用 JavaScript 的文章也可使用相同中等字級。

此調整針對既有字級造成的排版延遲，不代表字型網路載入、所有裝置效能或真實讀者核心指標已改善；量測及候選 CI 證據另行保存。

### 中文組字與快捷鍵

中文組字期間，編輯器讓 Enter、Escape、Backspace 與快捷鍵由輸入法處理，不將候選字確認誤作斜線區塊選取或 GitHub 保存。開始組字時關閉區塊選單；以 compositionstart／compositionend、isComposing 與舊式 229 標記辨識，組字結束後正常快捷鍵仍可使用。

回歸測試涵蓋真實 Chromium 編輯器內的三種事件標記、原生 CDP 中文組字與草稿保存，以及普通文字單次輸入的鍵盤 Undo／Redo。合成事件與 CDP 不代表實體 Windows／macOS／手機輸入法全矩陣驗收，也不代表圖片、表格或直接 DOM 插入的區塊已支援完整 Undo／Redo。[KeyboardEvent.isComposing](https://developer.mozilla.org/en-US/docs/Web/API/KeyboardEvent/isComposing)

### 完整來源與本機內容預覽

正式 CSP 下，通用 Trusted Types UI 清理器會剝除 script，不能用來解析要重新保存的整份文章。本輪在尚未正式發佈的候選中重現：保存後頁面 bootstrap 與 JSON-LD 都消失。新版使用編輯器閉包私有的 `hs-editor-document` policy，僅供完整文件的惰性 DOMParser 解析；不公開 policy 或將完整文件直接注入編輯器。CSP 只在文章路由的 `?admin=1` 允許此名稱，一般頁面仍只允許原 policy，hash-based script-src、Trusted Types 要求與通用 HTML 清理不變。

啟動及恢復草稿只匯入文章區域，匯入前移除可執行 script、事件屬性、srcdoc 與 javascript URL，保留 JSON-LD／JSON 資料。完整來源在編輯區之外保持原內容，保存前再清理文章區；恢復使用 DOM 節點複製，避免將非執行資料交给 UI innerHTML 清理器而遺失。此處的解析能力不代表任意 HTML 可以安全執行。[DOMParser 與惰性文件](https://developer.mozilla.org/en-US/docs/Web/API/DOMParser/parseFromString)

「本機預覽」包含目前尚未保存的內容，不送出 Git 保存或部署請求，也不代表候選部署或正式上線。預覽副本以原文章網址解析資產，段落與 FAQ 連結保持在該 blob 副本內；重新建立閱讀控制項與相關文章，移除編輯屬性並顯示雙語狀態說明。語言切換僅作用於預覽，不修改作者在編輯器中的偏好。預覽不啟用公開量測；彈窗被封鎖時顯示可重試的錯誤並保留作者內容。

預覽網址在預覽關閉後才釋放，避免原本固定三十秒後不能重新載入；編輯文件被關閉／重新載入或瀏覽器終止後，不能保證舊 blob 網址仍可重新載入，請重新開啟編輯器並建立預覽。副本存在本機瀏覽器，不是可分享的 Vercel Preview，也不以 noindex 宣称公開 Git 草稿是私人內容。

預覽的語言狀態會隨切換更新，延後產生的控制項沿用目前語言；不寫入作者的 Cookie 或 localStorage 偏好。此本機副本另停用 `/api/errors` 診斷送出，避免錯誤報告攜帶未保存副本的網址／錯誤細節；一般正式頁面的既有錯誤診斷政策不變。預覽測試同時監看實際 CWV、A/B、搜尋及錯誤端點。

瀏覽器的原生 CSP 報告不經過 JavaScript 錯誤處理器；blob 又繼承建立它的編輯文件 CSP。因此文章的 `?admin=1` 編輯文件另省略 `report-uri` 與 Reporting-Endpoints，讓其本機預覽不把被阻擋的未保存資源網址送到 `/api/csp-report`。此範圍也不再上報編輯文件自身的原生 CSP 違規；一般公开頁仍保留報告。資源來源、script hashes、Trusted Types 與其他 CSP 阻擋規則完全保留；測試刻意放入未核可圖片，確認資源確實遭阻擋、沒有網路圖片請求或原生報告。

### 已保存文章的上線狀態

「核對上線狀態」查詢目前 Git 已保存的文章版本，不保存新內容、不更動本機草稿、不觸發部署，也不把等待時間當成上線證據。查詢面板與保存提示分開；保存開始即取消舊查詢，延遲回應不能覆蓋新版本的狀態。重新開啟編輯器時只知道文章 blob SHA，不自行猜測上次保存 commit。

手機檢查重現原固定保存提示蓋住工具列按鈕。提示現在置於工具列內，工具列明確設定可用寬度並於小視窗內捲動；正文尾端依工具列實際高度留出空間，這項執行期 body 留白不寫入文章。360／390／768／1440 像素回歸使用正常點擊保存及核對按鈕，不使用 force 點擊掩蓋遮擋。

受登入保護的 `publication-status` 使用固定正式網址的 `site-version` 回應，核對 production、完整 Git SHA 與同庫身分，再讀取正式文章实际回傳的 HTML 位元組，與保存回執的 Git blob SHA 比較。符合時僅表示本次查詢的內容版本相同；生成、後續編輯或尚未部署都可能造成不同，不能僅由不同就認定作者內容遺失。保存 commit 是否為正式版本的祖先另以 GitHub compare 查詢，不以 main 變新或歷史 Ready 部署代表正在服務的正式版本。

`site-version` 為公開、no-store／noindex 的最小 Git 身分回應，只回傳 SHA、同庫名稱與環境，未設定 Vercel 系統變數時回傳 unknown；不回傳 Cookie、token、部署保護資訊或 commit 訊息。伺服器對正式站的查詢不轉送登入資訊、不接受使用者指定網域、不跟隨轉址；網路／讀取共用八秒取消訊號並限制回應大小，客戶端十秒後顯示逾時。受保護、不可讀、非 HTML、回應格式異常或來源失敗皆保留尚未確認，不當成零或通過。[Vercel 系統環境變數](https://vercel.com/docs/environment-variables/system-environment-variables)

同一保存 commit 若有同庫、同 SHA 的 PR 與 Vercel Preview 最新成功狀態，可開啟該版本的 Preview；不回退到失敗／inactive 後的舊成功狀態，不加入任何保護繞過參數。Preview 可能仍須 Vercel 登入。缺少有效 commit 的 no-op 保存、沒有對應候選 PR 或查詢失敗，均不憑空建立 Preview。GitHub/Vercel 查詢彼此獨立，部分來源失敗仍顯示其餘可核對事實。

此功能是版本觀察，**不是正式交付驗收**：`releaseVerified` 固定為 false；不宣称所有 CI 綠燈、不執行或取代 `_delivery.py` 的 exact-SHA jobs／steps／PR／Preview／人工視覺要求，以及正式 CI、部署與 smoke。完整發佈核可仍走 D-28，正式頁面內容相同也不能跳過發佈門檻。

### 保存前健檢與版本比較

「保存前健檢」只讀取目前內容，列出搜尋標題、摘要、空白正文、重複段落識別名稱、失效段落連結，以及圖片與雙語屬性的結構提示。不改寫文章、不給搜尋排名分數；空白正文阻止送出，與開啟時版本相比新增的提示需作者確認，既有提示可隨時手動檢查。這是有限的結構檢查，不能證明醫療正確性、翻譯品質或所有連結皆有效。

「比較版本」以文字呈現開啟時正文、目前編輯內容及此次讀取的最新保存版本，另可展開完整正文原始碼。比較不更新 baseSha、不自動合併，也不把外部版本插入可執行 DOM。對照後繼續輸入會提示畫面已過時；下載目前內容會在點擊時重新取得完整快照，包含最後一次輸入、格式與雙語屬性，以 UTF-8 純文字檔下載。下載不當成離開編輯，真正離開時仍保留未保存提醒。

Firefox 可能對同一次下載再發出 `downloadRequest=null` 的導覽事件。僅當事件來源是明確下載連結、連結與目的 URL 相同，且該 URL 仍屬編輯器追蹤中的匯出 Blob，才略過網站的離開確認；一般 Blob 連結或其他導覽不適用。比較面板的匯出在替換／清除時退役，工具列的舊版本草稿匯出則保留到編輯文件關閉，兩者生命週期分開。原生 `beforeunload` 保護仍獨立存在。下載、Navigation API 重複事件及真正離開的回歸分別檢查；沒有 Navigation API 的瀏覽器以實際下載與原生提醒檢查，不模擬成已有該 API。

409 衝突後保留原版本與本機草稿，阻止同一編輯器重送舊版。作者比較或下載後可重新開啟最新版本；重新開啟前必須成功保存最新本機草稿，舊版本草稿仍依既有程序另存備份。重新開啟不代表已合併舊內容。讀取失敗仍可繼續編輯及下載，不把失敗視為沒有外部修改。這批尚未代表全站編輯模式或所有貼上、表格與區塊 Undo／Redo 邊界都已驗收。

### 正文復原與雙語編輯

視覺編輯器使用文章範圍內的記憶體復原紀錄，讓直接插入的表格、迷思卡、警訊、摘要、流程圖與公式，和文字、貼上及字級格式使用同一復原順序。工具列提供「復原／重做」，鍵盤支援 Ctrl／Cmd+Z、Ctrl+Y 與 Ctrl／Cmd+Shift+Z；組字期間不接管快捷鍵。移動游標、更換段落或替換選取內容會分開輸入群組；復原後的新修改會清除舊重做分支。

歷史限於目前開啟的編輯工作階段，最多保留 64 個狀態，並依文章 HTML 的記憶體估算縮減至 8 MiB；至少保留目前與前一狀態，因此大型文章可能超過此估算。重新整理不保留復原堆疊；既有 OPFS／localStorage 草稿、Git 版本與衝突保護仍獨立運作。復原不改 baseSha、不撤銷已寫入 Git 的 commit，也不代表已正式發佈。

切換語言前先同步目前語言的作者文字，避免既有 data-zh／data-en 屬性將未保存內容還原。中文及英文正文皆可編輯；有分開正文的文章，區塊插入作用於目前語言的正文，作者需分別編寫另一語言，並不自動翻譯或鏡像新區塊。新增表格與迷思卡保留雙語欄位，英文模式使用英文提示。

隔離 Chromium 回歸涵蓋六種區塊、實際純文字與格式化剪貼簿貼上、字級、重做分支、巢狀雙語欄位、中英文表格保存再開啟；保存使用隔離回執，不寫入真實 CMS。這些結果不代表其他瀏覽器、手機系統復原選單、Word 全格式匯入或所有編輯流程已驗收。

快速返回後台再開啟同一文章時，安全離開成功後會換成乾淨的 iframe，避免 WebKit 的待完成空白頁導覽覆蓋重新開啟。既有草稿保存與衝突保護仍先完成，再移除舊編輯環境；此修正不表示實體 Safari 或全部跨瀏覽器編輯流程已驗收。

延後執行的公開閱讀初始化不在編輯模式執行，避免淡入樣式、分享區與作者卡在保存期間改變驗證過的文章，誤報新修改或寫入來源。保存請求期間真正的新輸入仍保留為未保存修改及復原草稿；不以忽略所有快照差異消除提示。

不改動文章的背景服務仍執行，包含 Service Worker 註冊；取得有效離線保存能力後，網路失敗仍可走既有重送佇列。隔離回歸核對註冊、保存失敗及佇列的版本與內容，不代表真實裝置已完成離線重送至伺服器。

## 資料表閱讀

現有文章的資料表置於獨立捲動區，窄螢幕時保留各欄的對照關係。讀者可左右滑動；鍵盤使用者可選取表格區後按方向鍵，沒有 JavaScript 亦可操作。這層包裝保留原表格、雙語文字及數值，不將研究結果改写為醫療建議。表格捲動亦不能替代圖表閱讀驗收。

## 圖表放大閱讀

正文的文字 SVG 圖表提供原生「放大圖表」控制。Enter 可開關；展開後，圖表在獨立區域上下左右捲動，關閉恢復原尺寸。沒有 JavaScript 亦可使用。原圖、標籤、數值、SVG id 與圖說保持原內容，不複製另一份圖，也不增加醫療 FAQ。列印時回到原本版面，避免把展開狀態的捲動區列印成裁切圖。

`_gen_diagram_readers.py` 在英文鏡像前處理 canonical；新增文字圖表亦沿用同一包裝，插入新圖時保留既有控制 id，圖表 viewBox 更新會刷新放大寬度。寬度是原 SVG 座標的閱讀底限；變形、裁切或圖像型文字仍須實際檢查，不能把這個幾何值當成全站無障礙核可。英文操作提示有獨立語言，不把未翻譯 SVG 宣稱為英文內容；既有英文 stub 發布限制不變。

編輯器保留原圖，隱藏閱讀控制，操作提示不作為正文可編輯段落。保存、草稿與預覽在作者雙語文字同步後，恢復 authenticated source 經既有消毒程序處理的控制項子節點、語言及展開屬性；保留控制項本身及原 SVG，不讓英文閱讀提示或展開狀態混入中文作者來源。回歸測試保持英文模式保存，核對原控制文字、作者英文摘要及重新開啟結果，不以先切回中文掩蓋序列化問題。新增樣式使用獨立檔，既有資產大小門檻維持。

圖表控制與捲動區保留頁首捲動留白。真正 200% 瀏覽器縮放的回歸，以 Chromium 原生縮放偏好及 CDP 的 zoom=2、scale=1 核對，而非單純改 deviceScaleFactor；從圖表按 Shift+Tab 返回控制項後，焦點與控制項中心均須可見，避免被固定頁首遮住。這項隔離瀏覽器測試不代表實體手機、原生 Safari 或螢幕閱讀器語音已完成驗收。

## 編輯器保存與草稿清理

編輯文件以自己的亮暗色背景繪製，避免透明 iframe 沿用後台淺色畫布。工具列、插入選單、鍵盤焦點與成功訊息保留可讀對比；頁尾不再整體淡化。這些編輯樣式不寫入文章來源。

公開閱讀與編輯畫面的大綱、連結、推薦卡及作者資訊使用相配的暗色表面與文字；警訊保留紅色、迷思解答保留綠色。文章圖表保留成組的淺色畫布與文字變數，避免原有彩色嚴重度列、SVG 圖例及圖說混用亮暗配色。這不改醫療文字、數值或作者行內樣式。五篇試點的暗色回歸涵蓋 360、390、768、1440px 的公開與編輯畫面，實際捲動內容並等待正常淡入後檢查文字對比；SVG、漸層等自動工具無法判定的項目另保存人工檢視清單，不能據此宣稱全站或完整編輯器符合 WCAG。

GitHub 已回覆有效的保存版本，但 OPFS 或其他本機草稿清理未能確認時，仍不得宣稱草稿已刪除。編輯器會以新的文章版本保存最新復原草稿；成功後允許返回後台，離開前再次保存最新輸入。復原草稿寫入失敗則保留編輯器與作者文字。明確「捨棄」仍要求確認兩種儲存的草稿都已清除；不因無法讀取 OPFS 而假定不存在，也不把已確認的 GitHub 保存再次排入離線重送。

中英文切換的 `display` 僅是編輯畫面的狀態。草稿、Undo/Redo 快照與提交來源保留驗證過的原始文件中 `proseZh`／`proseEn` 的 style，避免英文模式存檔改變中文 canonical 的預設顯示。

## 初次載入的文章目錄

`_gen_reader_navigation.py` 在英文鏡像前，以作者既有 h2 標題產生原生目錄。目錄隨 HTML 一起顯示，避免共享腳本下載後才插入大區塊、推動正在閱讀的正文；沒有 JavaScript 也能展開、收合與跳到段落。雙正文文章的英文目錄指向英文段落，行內雙語文章則沿用原段落 id。標題內容和來源 HTML 不由目錄產生器重寫。

這是生成的閱讀介面，沿用 CMS 已有的 reserved helper 清理：存檔移除目錄，由正常產生流程依最新標題重建，不把舊目錄當作作者正文。目錄也排除於全文匯出，且不產生醫療 FAQ。動態閱讀時間、列表篩選與字型載入仍可能造成位移；隔離測試的改善不能宣稱為真實使用者的 Core Web Vitals 或流量成長。

編輯器在匯入驗證過的作者來源時先移除生成目錄並合併相鄰文字節點，讓實際編輯 DOM 與 Undo/Redo 快照的游標路徑一致；不等到保存快照才移除這個閱讀元件。作者正文、圖表與原始文件仍依既有保存及版本保護處理。

## 文章索引篩選與載入穩定性

`_gen_blog_filter.py` 在英文鏡像前，依索引頁既有卡片產生分類、主標籤、數量與搜尋欄位；只替換保留的輔助區塊，不重寫文章卡片、醫療內容或 URL。樣式來自 `assets/blog-filter.css`。共享腳本只綁定既有控制項，不再於載入後插入整塊篩選列。

互動事件與初始條件完成後才開放操作，避免先輸入、稍後又被重建欄位清空。沒有 JavaScript 時不顯示不可操作的篩選列，所有文章原生連結仍可直接使用。標籤以中文原值維持同一分組、中英文標示分別顯示；原英文標籤 query 仍轉為相同分組，分類與標籤的按下狀態提供給輔助工具。

受控延遲腳本測試判斷篩選列是否再次推動文章。這是載入與操作驗證，不代表真實使用者 Core Web Vitals、點擊率或搜尋排名已改善；正式結果依同一版本的候選／main CI、Preview 與部署驗收另記。

Lighthouse 的準備頁另保存 Chrome 版本、語言、畫面尺寸、原頁面選用字型，以及固定中英文範例的系統替代字型與尺寸。診斷只讀公開排版資訊，不讀取或保存 cookie、storage、作者文字或完整 HTML；固定範例使用系統字型，不新增 Google Fonts 請求，讀取後立即移除。這份 `font-environment` artifact 綁定候選完整 SHA，與 Lighthouse 實際量測報告分開；它不是讀者統計，也不代表準備頁的視窗就是正式 Lighthouse 的量測視窗。既有三次桌面量測、字型載入政策及效能門檻保持原設定。
