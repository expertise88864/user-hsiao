# 第一方 CWV 分群定義 v1

此契約補充既有 `web-vitals-6` 回報，不改 GA4 事件名稱、值、收件次數或總覽的歷史定義。它不是 Google CrUX，也不代表所有訪客。

## 收件欄位

只有既有第一方 beacon 加上以下三個欄位；不是新的追蹤服務：

| 欄位 | 定義 |
|---|---|
| `contextVersion` | 數字 `1`；舊或無效版本不推測回填 |
| `viewportBand` | 首次有資格啟動量測時 CSS 視窗寬度：`narrow` <768、`medium` 768–1199、`wide` ≥1200；無法取得是 `unknown` |
| `assetEpoch` | 實際執行 `/blog/blog-shared[.min].js` URL 中唯一、有效的八位 `?v=`；無法證明是 `unknown` |

每個文件固定首次量測視窗，resize、zoom 或量測腳本失敗重試不換群；prerender 尚未啟動量測，活化後才取得視窗。視窗群不是手機／平板／桌面硬體分類。資產 epoch 不是 Git SHA：文件與 audit commits 可以共用同一批資產，正式版本須另對照交付紀錄。

Server 僅保存白名單欄位，不保存原始寬度、UA、正文、查詢、Cookie 或新增訪客識別資訊。既有 ID 僅用於同一頁面指標的重複回報去重。Preview、編輯、bot、自動測試、隱私偏好與管理者排除保留；新欄位不讓排除來源重新入列。

## 讀回與比較

總覽仍使用每指標最近最多 1000 筆回報、滾動最多 30 天收件時間；有效標準量測優先於舊方法，同 ID 取最新回報，p75 由原始樣本 nearest-rank 計算。CLS 儲存值除以 1000 的規則不變。

先完成總覽相同的時間／方法篩選與全域 ID 去重，再依 epoch／視窗分群。同一 ID 上下文不同也只算最新一筆。無有效 v1 欄位的歷史資料顯示「未知」，不是零或推測裝置。

後台總覽與分群並列，每群顯示方法、p75、樣本數與保留樣本收件時間。每指標最多顯示最近收件的 24 群；省略群數及樣本數明示，省略資料仍在總覽。GA4 事件平均不能還原 p75 或此分群，缺少時明示不支援。

時間是收件時間，不是造訪時間，也不保證每天有資料。樣本數不是不重複訪客數；INP 僅涵蓋有可量測互動的頁面。小樣本、不同期間／方法／視窗群不可直接當成發佈改善證據。此版本開始後才有新 context，不回填舊資料；工程驗收不製造正式訪客回報。

## 驗證邊界

API 與瀏覽器 fixtures 驗證收件／讀回、去重、p75、未知資料、群數上限、隱私排除、重試及鍵盤顯示，均使用隔離假資料。這不是 Production KV 實際訪客量測或人類可用性研究。正式交付仍須 exact-SHA 候選與正式 CI、Preview／browser、適用 Ubuntu 人工視覺核可及 smoke；分群可用不等於 P-07、CTR 或全站效能已完成。
