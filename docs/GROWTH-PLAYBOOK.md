# GROWTH-PLAYBOOK.md — 搜尋成效診斷與改善流程

> 本文件記錄可重複執行的判讀方法。每次調整先查當期 GSC 與線上版本；不能把過去的技術檢查通過、網站年齡或作者身分，直接當成現在流量低的原因。私人 GSC 數據、查詢匯出與帳號資訊留在本機，不提交至公開網站。

## 1. 先區分問題，再選擇工作

以 GSC「成效 → 搜尋結果」記錄日期、搜尋類型、國家、裝置、點擊、曝光、CTR 與平均排名。Google 搜尋點擊不是不重複訪客人數。

- **目標地區曝光少**：先確認重要中文頁已索引，再找實際病人查詢與文章涵蓋的問題是否吻合。全世界曝光量不能替代台灣讀者的觸及量。
- **曝光有、點擊少**：依頁面與查詢檢查排名、意圖、標題和摘要。先做少量可量測調整，避免一次重寫所有文章。
- **曝光下降**：比較相同長度期間，排除尚未完整的日期；同時讀點擊、排名、國家、裝置及受影響頁面。曝光下降不等於排名下降，更不直接證明演算法處罰。
- **品牌搜尋集中**：把指名與非指名搜尋分開觀察。首頁或作者頁的成效不能代表疾病文章已能吸引新讀者。

GSC 表格可能省略隱私查詢；頁面與資源彙總方式也不同。不要把可見查詢列總和當成全部需求，不要把不同維度列數直接加總成全站總計。少量曝光下的 CTR 波動不足以判定改版成敗。

依據：[GSC 成效報表](https://support.google.com/webmasters/answer/7576553?hl=en)、[Google 流量下降診斷](https://developers.google.com/search/docs/monitor-debug/debugging-search-traffic-drops)。

## 2. 索引與線上部署要分開核對

1. 比對 GSC 報表更新日、個別 URL 上次檢索日，以及目前線上的 HTTP 狀態、canonical、robots 與 hreflang。
2. 對照 DECISIONS.md 的草稿、合併頁與英文 stub 政策。刻意 noindex 和正常重新導向不是待消除的錯誤；不要為了報表歸零把草稿加入 sitemap。
3. 「已找到」或「已檢索」但未索引，先確認內容完整、可存取、已有可爬取的情境連結。索引申請成功只表示 Google 接受要求，不能宣稱已收錄，也不需反覆申請同一頁。
4. Sitemap 讀取成功不保證每頁索引。CI 成功也不代表 Vercel 部署成功；需確認實際部署及線上 HTML 確實包含改動。

依據：[網頁索引報表](https://support.google.com/webmasters/answer/7440203)、[要求重新檢索](https://developers.google.com/search/docs/crawling-indexing/ask-google-to-recrawl)。

## 3. 站內改善順序

1. **既有內容的搜尋入口**：標題清楚交代疾病、問題與文章用途；縮減冗長的期刊名稱、縮寫與重複品牌文字。摘要說明讀者能找到什麼，不以單一研究的效益數字當成對個人的保證。Google 可能改寫標題與摘要，沒有固定字數能保證完整顯示。
2. **先回答，再展開**：從現有、已引用的醫療內容重述答案，讓病人容易找到症狀、檢查、選擇與回診問題。新增臨床宣稱、劑量、數字或醫療建議必須由站主確認，遵守 ARTICLE-STANDARDS.md。
3. **情境連結**：先檢查 D-23 的既有叢集。只補真實缺口，使用可爬取的 href 與能描述目的頁的文字；不用重複關鍵字或大量互連取代內容。
4. **新增文章**：依目標地區的 GSC 查詢與站主實際常見問題補缺口。避免同一問題拆成多篇相似薄頁，也不為追逐日期而改發布時間。
5. **作者資訊**：維持住院醫師身分與來源透明。外部檔案 URL 必須由站主提供且能驗證；不自行添加醫院、掛號資訊、專科資格或未發生的獨立審閱。

依據：[標題連結](https://developers.google.com/search/docs/appearance/title-link)、[摘要](https://developers.google.com/search/docs/appearance/snippet)、[有用可靠的內容](https://developers.google.com/search/docs/fundamentals/creating-helpful-content)、[可爬取連結](https://developers.google.com/search/docs/crawling-indexing/links-crawlable)。

## 4. 驗證與追蹤

- 編輯 HTML 後執行完整生成鏈、固定點與適用 CI；英文鏡像由產生器更新。遵守 AGENTS.md 的本機 CI、獨立審查、推送與該 SHA 遠端 CI 閘門。
- 本機保存改動前基準、改動頁面、日期、假設、驗證與部署結果。只有確認上線後，才開始計算改善後期間。
- 以完整 28 天對前 28 天觀察，再以三個月確認方向；量少時延長觀察。先看台灣非指名曝光與文章點擊，再看相同查詢／排名條件下的 CTR。
- 如遇大幅變動，依 §1 回查資料與索引。不要因一週百分比警示反覆改 URL、canonical 或全站標題。
- 社群分享、外部作者檔案與投稿需由站主選擇並授權執行。不買連結、不量產薄頁，也不保證特定期限的排名或點擊成長。
- AI 引用與 Google 搜尋流量分開量測。研究環境中的引用增幅不能直接套用本站；llms.txt、FAQ schema 或增加統計數字都不構成排名保證。
