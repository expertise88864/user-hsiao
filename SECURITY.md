# Security policy — HsiaoEye

This document records the production security posture of
`hsiao.chendermatologist.com` and the operator's runbook for keeping
it that way. It is NOT a public bug bounty page — there is no monetary
reward — but every report listed under "Reporting" is read and acted on.

## Reporting a vulnerability

Please email **f94001115@gmail.com** with subject `[security] <short
summary>`. Include:

- Affected URL or endpoint
- Reproduction steps (curl invocation, browser steps, etc.)
- What the bug enables (data leak, XSS, account takeover, ...)
- Your timeline for public disclosure

You'll get a same-day acknowledgement and, in most cases, a fix within
72 hours. We do not require a CVE before patching; we will assign one
post-fix if the impact warrants it.

## Defense-in-depth controls in production

| Layer                          | Mechanism                                              |
|--------------------------------|--------------------------------------------------------|
| Transport                      | HSTS `max-age=63072000; includeSubDomains; preload`    |
| Content sniffing               | `X-Content-Type-Options: nosniff`                      |
| Clickjacking                   | `X-Frame-Options: SAMEORIGIN` + CSP `frame-ancestors`  |
| Cross-origin embedding         | COOP `same-origin-allow-popups`, CORP `same-site`      |
| Browser API surface            | `Permissions-Policy` denies camera/mic/geo/payment/usb |
| XSS                            | Hash-based CSP `script-src` + Trusted Types policy     |
| 3rd-party script tampering     | SRI `integrity="sha384-…"` on every jsdelivr load      |
| Privilege boundary             | Admin behind signed cookie + Vercel matcher exclusion  |
| Public API abuse               | Per-IP / per-session token-bucket rate limiting        |
| Form submission                | Edge-validated payloads + size caps                    |
| Body content (admin save)      | Server-side `stripRuntimeHelpers + halfwidthToFullwidth` |
| Bot training opt-out           | `robots.txt` disallows GPTBot/ClaudeBot/CCBot/etc.     |
| DNT honoring                   | GA4 + Clarity short-circuit when `DNT=1`               |

The full CSP is generated by `_gen_csp_hashes.py` and enforced by
`middleware.js` on every HTML response. See those files for the live
hash list.

## HSTS preload — submission runbook

This site already meets the four preload prerequisites, listed here so
the owner can re-verify with one `curl` whenever the config changes:

1. **Valid HTTPS** — Vercel auto-renews via Let's Encrypt.
2. **Redirect HTTP → HTTPS** — Vercel default.
3. **All subdomains over HTTPS** — `includeSubDomains` set.
4. **HSTS header with `max-age >= 31536000` and `preload`** — set to
   `63072000` (2 years).

Verify via:
```bash
curl -sI https://hsiao.chendermatologist.com/ | grep -i strict-transport
# Expect: Strict-Transport-Security: max-age=63072000; includeSubDomains; preload
```

Submit the apex domain (`chendermatologist.com`) to the Chromium
HSTS preload list at <https://hstspreload.org>. **Read the warnings
on that page first** — once submitted, removing the domain takes
weeks and break HTTP fallback for everyone with that browser version.
Submission is irreversible without a coordinated browser-side rollback.

After the apex is on the list, the subdomain `hsiao` inherits via
`includeSubDomains`. No separate submission needed.

## CSP policy summary

- `script-src 'self' '<sha256-…>' (repeat 170+) <CDN allowlist>` — every
  inline script is hashed by `_gen_csp_hashes.py`; reflected-XSS injects
  fail the hash check.
- `style-src 'self' 'unsafe-inline' …` — kept `'unsafe-inline'` because
  scattered dynamic style attributes are impractical to hash and CSS
  cannot execute JS. Tradeoff accepted.
- `require-trusted-types-for 'script'` + `trusted-types default hs-policy`
  — dynamic `innerHTML` and `eval` family go through a sanitizing policy
  defined in `blog/blog-shared.js`.
- `report-uri /api/csp-report` — violations are POSTed; the endpoint
  persists last 200 to KV and admin can view aggregates at
  `/api/admin/csp` (admin dashboard CWV tab).

## SRI policy

Every dynamically-injected jsdelivr `<script>` and `<link rel="stylesheet">`
in `blog/blog-shared.js` carries an `integrity="sha384-…"` attribute. To
bump a version:

```bash
# 1. Pick the new full version (NOT major-only) from jsdelivr.
# 2. Compute the new hash:
curl -sL https://cdn.jsdelivr.net/npm/<pkg>@<version>/<path> \
  | openssl dgst -sha384 -binary | openssl base64 -A

# 3. Update both the URL and the integrity= in blog/blog-shared.js
#    in the same commit.
```

If you ship the version bump without bumping the hash, the browser
will refuse to execute the script — feature breaks but no exec. Tested
in production.

## Rate limiting

| Endpoint                    | Limit              | Identifier        |
|-----------------------------|--------------------|-------------------|
| `/api/csp-report`           | Origin-allowlisted | Origin header     |
| `/api/cwv-ingest`           | 30 / minute        | Cookie or IP      |
| `/api/push/subscribe`       | 10 / minute        | Cookie or IP      |
| `/api/errors`               | 60 / minute        | IP                |
| `/api/admin/*`              | 30 / minute        | Session cookie    |

Implementation lives in `api/_rate_limit.js`. Each container is in-memory
isolated — sufficient for accidental abuse and small DDoS bursts;
larger attacks rely on Vercel WAF.

## What is NOT in scope

- Bug bounty payouts. This site is a personal patient-education project.
- Vulnerabilities in third-party services (Vercel, Google Analytics,
  Microsoft Clarity, jsdelivr) — report directly to those vendors.
- Issues that require an admin-authenticated session you obtained via
  the operator's own credentials.
- Theoretical CSP relaxations like `style-src 'unsafe-inline'` —
  decision is documented above.
